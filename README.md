## 🎮 游戏概述

### 1.1 游戏定位

| 项目 | 内容 |
|------|------|
| **游戏名称** | 世界线·抉择 (Worldline: Choice) |
| **游戏类型** | AI驱动互动叙事 / 文字冒险 / 战术推演 |
| **核心体验** | 「你就是主角，重写传奇」 |
| **目标用户** | 喜爱剧情、历史、文学、RPG、策略推演的游戏玩家 |
| **单局时长** | 15-45分钟（短篇）/ 1-2小时（长篇）/ 10-30分钟（战术推演） |

### 1.2 核心概念

《世界线·抉择》是一款基于固定世界观的AI互动叙事游戏。玩家在熟悉的历史、名著或原创世界中扮演关键角色，通过**预设选项**或**自由输入**来推动剧情发展。

**两大模式**：
- **叙事模式**：自由探索，角色扮演，AI实时生成剧情
- **战术模式**：千人对战，多步骤战术推演，d20强制检定

**一句话描述**：
> 在三国成为枭雄，在西游改写天命，在千人对战中施展连环计——你的每个选择，都将创造独一无二的世界线。

### 1.3 游戏特色

1. **混合抉择系统**：4个精心设计的预设选项 + 1个自由输入通道
2. **战术多步骤判定**（v3.3）：支持复杂战术推演，步骤依赖、关键步骤中断
3. **防套利机制**（v3.3.2）：勉强成功降级、指挥链过载、信息泄露，封死「垫刀流」
4. **严格d20检定**：真正的挑战性，不是想怎样就能怎样
5. **动态叙事**：AI实时生成剧情，每次游玩都是全新体验
6. **状态追踪**：属性、关系、道具、标签多维度记录玩家选择的影响
7. **多结局收集**：每条世界线包含5-15个不同结局

每个抉择点采用**固定格式**：

```
┌──────────────────────────────────────────────────────────────┐
│  【抉择点名称】                                               │
│                                                              │
│  场景描述文本...                                              │
│                                                              │
│  ┌────────────────────────────────────────────────────────┐  │
│  │  A. 【行动类】具体行动描述                               │  │
│  │     标签：勇敢 · 可能触发战斗                             │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │  B. 【对话类】具体对话/交涉描述                          │  │
│  │     标签：智慧 · 可能获得情报                             │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │  C. 【观察类】观察/等待/暗中行动描述                     │  │
│  │     标签：谨慎 · 可能发现隐藏要素                         │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │  D. 【特殊类】基于当前状态的特殊选项                     │  │
│  │     标签：[持有特定道具/达成特定条件时显示]               │  │
│  ├────────────────────────────────────────────────────────┤  │
│  │  💭 我另有打算...（点击输入自定义行动）                  │  │
│  └────────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 四类预设选项设计规范

**模式一：阵营/立场选择**
```
A. 【支持甲方】理由/方式
B. 【支持乙方】理由/方式
C. 【保持中立】寻找第三条路/暂时观望
D. 【特殊条件】基于状态的独特选择
```

**模式二：策略/方法选择**
```
A. 【直接方案】正面突破，高效但风险高
B. 【迂回方案】侧面渗透，耗时但稳妥
C. 【非常规方案】利用环境/第三方/诡计
D. 【特殊条件】基于能力的专属方案
```

**模式三：价值观/道德选择**
```
A. 【利己】优先保障自身/己方利益
B. 【利他】牺牲自己帮助他人
C. 【平衡】寻求多方共赢（难度更高）
D. 【特殊条件】基于信仰/原则的立场
```

**模式四：风险/收益选择**
```
A. 【激进】高风险高回报，梭哈一搏
B. 【稳健】中等风险中等收益，稳中求进
C. 【保守】规避风险，宁可错过也不犯错
D. 【特殊条件】基于信息的特殊判断
```

### 3.3 自由输入系统

AI需要识别并归类玩家的自由输入：

| 输入类型 | 识别关键词 | 处理方式 |
|----------|-----------|----------|
| **战斗行动** | 打、杀、攻、砍、射、战 | 计算战力，触发d20检定 |
| **对话交涉** | 说、问、谈、劝、骗、求 | 分析话术，进行d20检定 |
| **潜行观察** | 看、躲、藏、等、跟、查 | 进行隐匿/观察检定 |
| **物品使用** | 用、吃、喝、点、扔、给 | 检查物品栏，触发效果 |
| **移动位置** | 走、跑、跳、爬、进、退 | 改变场景位置 |

## 🎯 战术多步骤判定系统 (v3.3)

### 4.1 系统概述

战术多步骤判定系统支持玩家在**大规模战斗场景**中设计复杂的分步战术，通过**数字标识**标记行动顺序，系统自动建立步骤依赖链并进行d20强制检定。

**适用场景**：
- 千人对战（两军对垒，各拥士卒千余）
- 攻城战（多兵种配合，多阶段进攻）
- 伏击战（埋伏、诱敌、合围）
- 突围战（断后、佯攻、主力撤离）

### 4.2 数字标识多步骤判定（v3.3.1）

#### 使用规则

**顺序执行**（不同数字）：
```
1. 派100人偷袭粮草
2. 派500人埋伏两侧  
3. 主力诈败诱敌
4. 合围击杀
```

**同时执行**（相同数字）：
```
1. 派左翼佯攻
1. 派右翼包抄      ← 与上一步同时
2. 主力正面冲击    ← 前两步完成后执行
```

**支持的分隔符**：
- `1.` `2.` - 英文句点
- `1、` `2、` - 中文顿号
- `1)` `2)` - 括号格式

### 4.3 复合步骤检定

当多个行动共享同一数字时：
1. 每个子行动**独立检定**（DC+2，同时执行更困难）
2. 结果合并计算：
   - 全部成功 → 步骤成功
   - 部分失败 → 勉强成功/勉强失败
   - 关键失败 → 步骤失败

### 4.4 步骤依赖与影响链

系统自动识别每步的战术目的，并建立依赖链：

```
步骤1: 派100人偷袭粮草 (DC 12)
  ├─ 成功 → 敌军混乱，步骤2 DC-3
  ├─ 勉强成功 → 效果有限，步骤2 DC-1
  └─ 失败 → 敌军警觉，步骤2 DC+2

步骤2: 派500人埋伏 (DC 10，受益于步骤1)
  ├─ 成功 → 伏击就绪，步骤3 DC-3
  ├─ 勉强成功 → 埋伏有漏洞，步骤3 DC-1
  └─ 失败 → 埋伏暴露，计划受影响

步骤3: 主力诈败诱敌 (DC 14，关键步骤)
  ├─ 成功 → 敌军入套，步骤4 DC-3
  ├─ 勉强成功 → 敌军起疑，步骤4 DC不变
  └─ 失败 → 计划失败，可能中断

步骤4: 合围击杀 (DC 8，关键步骤)
  ├─ 成功 → 敌军全军覆没
  └─ 失败 → 功亏一篑
```

### 4.5 关键步骤机制

部分步骤被标记为**关键步骤**（诱敌、偷袭、总攻、合围）：
- 关键步骤失败（非勉强失败）→ 后续步骤可能**跳过**
- 例如：诈败失败 → 敌军未入套 → 合围步骤取消

### 4.6 支持的句式模式（10+种）

| 模式 | 示例 | 检测 |
|------|------|------|
| 派X人做Y | 派100人偷袭粮草 | ✓ |
| 剩下/剩余X人 | 剩下400人诈败诱敌 | ✓ |
| 主力/亲卫 | 主力部队正面迎敌 | ✓ |
| 亲率/亲自 | 本将亲率亲卫冲锋 | ✓ |
| 然后/接着 | 然后合围击杀 | ✓ |
| 再/又 | 再派预备队包抄 | ✓ |
| 首先...最后 | 首先侦察，最后总攻 | ✓ |
| 第一步...第三步 | 第一步诈降，第三步围歼 | ✓ |
| 一边...一边 | 一边骚扰一边集结 | ✓ |
| 同时 | 同时左翼佯攻、右翼包抄 | ✓ |
| 继而/末了 | 继而伏兵四起，末了合围 | ✓ |

## 🛡️ 防套利机制 (v3.3.2)

### 5.1 问题背景

在 v3.3/3.3.1 版本中，发现玩家可以通过「垫刀流」套利：
- 用低成本 filler 步骤（如"派10名老弱残兵呐喊"）蹭取高额 DC-3 加成
- 步骤越多越好，因为勉强成功也算成功
- 风险可控，因为关键步骤失败只是中断，没有额外惩罚

**v3.3.2 引入防套利机制三部曲**，让策略回归真实。

### 5.2 补丁 A：勉强成功降级

| 结果 | 对当前步骤 | 对后续步骤加成 |
|:---:|:---:|:---:|
| 大成功 | 超额完成 | DC-5 |
| 成功 | 顺利完成 | DC-3 |
| **勉强成功** | 完成但有代价 | **DC-1**（原为DC-3）|
| 勉强失败 | 失败但可补救 | 无加成，可能DC+2 |
| 失败 | 明确失败 | 无加成，DC+5 |
| 大失败 | 灾难性后果 | 无加成，DC+5，可能信息泄露 |

**设计意图**：防止玩家用低成本 filler 步骤「垫刀」蹭加成。只有真正的成功才能给后续步骤带来显著优势。

**效果对比**：
```
【垫刀流示例】
v3.3.1：步骤1勉强成功 → 步骤2 DC-3（蹭到满额加成）
v3.3.2：步骤1勉强成功 → 步骤2 DC-1（仅基础加成）
```

### 5.3 补丁 B：指挥链过载

当步骤数超过 **3步** 时：
- 第4步起，每多一步，**该步骤及之后所有步骤 DC+1**
- 代表指挥链过长、部队协调困难

```
示例：6步计划
步骤1: DC 12（正常）
步骤2: DC 10（正常）
步骤3: DC 14（正常）
步骤4: DC 15（+1 过载）
步骤5: DC 18（+1 过载）
步骤6: DC 10（+1 过载）
```

**例外**：复合步骤（相同数字标记）算作**单一步骤**评估过载。

**设计意图**：抑制无脑堆步骤，鼓励精简高效的战术设计。

### 5.4 补丁 C：信息泄露机制

任何步骤出现 **大失败（自然1）** 时：
1. 该步骤的战术信息可能被敌方获取
2. 敌方掌握的信息越多，**所有后续步骤 DC 累加+2**
3. 信息泄露**无法消除**，持续整场战斗

```
示例：信息泄露叠加
步骤2大失败 → 后续步骤 DC+2（信息泄露×1）
步骤4大失败 → 后续步骤 DC+4（信息泄露×2）
```

**叙事表现**：
- 士兵溃逃泄露埋伏位置
- 斥候被俘吐露全盘计划
- 暗器失手暴露偷袭意图

**设计意图**：让大失败有长期后果，增加战术失误的真实代价。

### 5.5 防套利效果验证

| 策略 | v3.3.1 评估 | v3.3.2 评估 |
|:---|:---:|:---:|
| **无脑垫刀流** | ✅ 可行（勉强成功蹭加成） | ❌ 低效（仅DC-1） |
| **精简高效战术** | ✅ 可行 | ✅ 更优（无过载惩罚） |
| **极限多步骤** | ✅ 可行 | ❌ 自惩罚（过载+DC） |
| **高风险赌博** | ⚠️ 方差大 | ⚠️ 方差更大（信息泄露） |

## 🎲 d20检定系统

### 6.1 核心检定公式

```
d20 + (属性-10)/2 >= DC
```

- **d20**：掷一个20面骰（1-20）
- **属性修正**：(属性值-10)/2，向下取整
- **DC**：难度等级（Difficulty Class）

### 6.2 难度等级

| 等级 | DC | 成功率（无修正）|
|:---:|:---:|:---:|
| 简单 | 5 | 90% |
| 普通 | 10 | 70% |
| 困难 | 15 | 50% |
| 极难 | 20 | 30% |
| 不可能 | 25+ | 10% |

### 6.3 结果等级

| 超出DC | 结果 | 效果 |
|:---:|:---:|:---|
| +10以上 | **大成功** | 超额完成，额外收益 |
| +5~9 | **成功** | 顺利完成 |
| 0~4 | **勉强成功** | 完成但有代价，v3.3.2仅DC-1加成 |
| -1~-4 | **勉强失败** | 失败但可补救 |
| -5~-9 | **失败** | 明确失败，承担后果 |
| -10以下 | **大失败** | 灾难性后果，v3.3.2触发信息泄露 |

**特殊规则**：
- **自然20**：必成功，视为大成功
- **自然1**：必失败，视为大失败

### 6.4 检定示例

**场景**：诈败诱敌
- DC：14（关键步骤）
- 玩家魅力：16（修正+3）

```
掷骰结果：11
11 + 3 = 14 >= 14 → 勉强成功！

叙事：你拖枪便走，大喊"敌将厉害"。
但演技有些生硬，敌将虽有疑心，仍追了过来。

后果：
- 敌军追击（勉强成功，目标达成）
- 但敌军警觉（勉强成功，有代价）
- 后续步骤仅DC-1加成（v3.3.2）
```

## 🤖 AI叙事系统

### 9.1 核心Prompt架构

引擎生成三种Prompt供AI使用：

**系统Prompt** (`get_system_prompt()`)
- 包含世界观、当前状态、历史记录
- 用于生成新的场景和选项

**行动Prompt** (`get_action_prompt()`)
- 包含当前场景、玩家输入
- 用于评估可行性并推演后果

**结局Prompt** (`get_ending_prompt()`)
- 包含完整游戏回顾
- 用于生成结局剧情

### 9.2 AI生成流程

1. **场景生成**：基于世界观和当前状态生成场景
2. **冲突识别**：自动识别场景中的核心冲突
3. **选项生成**：生成4个不同方向的选项（A/B/C/D）
4. **可行性评估**：对自由输入进行严格客观的可行性检查
5. **d20检定**：如需，执行强制检定
6. **后果推演**：推演行动后果，更新状态
7. **结局判定**：判断是否达到结局条件

### 9.3 严格可行性评估

自由输入选项会进行**严格客观的可行性评估**：

- ✅ **客观能力检查**：玩家是否有执行此行动所需的技能/能力/物品
- ✅ **情境限制检查**：环境、时间、物理限制是否允许
- ✅ **信息掌握检查**：不能假设玩家知道未发现的秘密
- ✅ **合理性评估**：符合游戏世界的基本逻辑和物理法则
- ✅ **不刻意迎合**：不会因为玩家想这么做就让其轻易成功
- ✅ **不刻意刁难**：不会因为玩家想这么做就故意使其失败

## 🚀 快速开始

### 安装

```bash
git clone https://github.com/caoyachao/worldline-choice.git

```

### Python API 使用

```python
from worldline_engine import WorldlineEngine

# 创建游戏引擎
game = WorldlineEngine()

# 开始游戏
game.start_game(
    world_setting="魔兽世界 - 巫妖王之怒时期",
    player_role="潜行者",
    player_name="玩家"
)

# 获取AI Prompt用于生成场景
system_prompt = game.get_system_prompt()

# 处理玩家行动（AI返回的响应）
result = game.process_action(
    player_input="调查那个神秘女子",
    ai_response={
        "intention": "调查",
        "feasible": True,
        "narrative": "你悄悄跟踪神秘女子，发现她进入了黑帮据点...",
        "consequences": {
            "attribute_changes": {"智力": 1},
            "secrets_learned": ["女子是黑帮成员"]
        }
    }
)

# 保存游戏
game.save_game("save_001")
```

## 📝 设计原则

### 1. 严格可行性评估
- 不刻意迎合玩家，也不刻意刁难
- 完全基于客观事实判断
- 失败也应该产生有意义的后果

### 2. 真正的挑战性（d20强制检定）
- 不是玩家想怎样就能怎样
- 运气和策略同样重要
- 大成功和大失败都有戏剧性

### 3. 防套利设计（v3.3.2）
- 防止「垫刀流」等机制漏洞
- 奖励真正的成功，惩罚无脑堆步骤
- 让战术失误有真实代价（信息泄露）

### 4. 开放式叙事
- 不预设固定剧情
- AI根据玩家行为实时生成内容
- 每个玩家体验独一无二

### 5. 永不丢失历史
- 所有回合完整记录永久保存
- 分层摘要用于AI上下文
- 支持完整复盘

## 📜 版本历史

### v3.3.2 (2026-03-31) - 平衡补丁版
- **防套利机制三部曲**
  - **补丁 A**：勉强成功仅提供 DC-1 加成（原为 DC-3）
  - **补丁 B**：步骤数超过 3 时，第 4 步起每步 DC+1（指挥链过载）
  - **补丁 C**：大失败触发信息泄露，后续步骤 DC 累加惩罚
- **封死「垫刀流」套利**：filler 步骤不再是无成本蹭加成
- **保留策略深度**：奖励真正的成功，惩罚无脑堆步骤

### v3.3.1 (2026-03-31) - 数字标识版
- **数字标识多步骤判定**
  - 不同数字 = 顺序执行
  - 相同数字 = 同时执行（复合检定）
  - 支持 `.` `、` `)` 三种分隔符
- **复合步骤独立检定**
  - 每个子行动独立掷骰
  - DC+2（同时执行更困难）
  - 结果合并计算

### v3.3 (2026-03-31) - 战术判定版
- **战术多步骤判定系统**（完整版）
